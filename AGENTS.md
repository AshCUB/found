# Found – notes for agents

- Build: `npm run build` (Vite). Note `dist/` is committed and the build rewrites it; to only check that it compiles, use `npx vite build --outDir <temp dir>` (the 404 plugin still writes `dist/404.html`, delete it after).
- No test suite or linter is configured.
- Supabase: SQL in `supabase/migrations/` is run by hand in the dashboard SQL editor, in filename order. Front-end uses only the publishable/anon key (`.env`, see `.env.example`).
- Desk tab: catalog is generated from the user's desk decor source folder (`Materials/` + `<Category>/<free|low|med|high>/`) by `npm run import-desk-decor -- "<folder>"`, which writes `src/data/deskDecorCatalog.json` (edit names/descriptions/sizes there; new items get an empty description, shown in the purchase panel; items are matched by file name, never change ids), the images in `public/images/desk/{materials,decorations}/<id>.webp`, and `supabase/desk_decor_prices.sql` (user must run it in the SQL editor after every import). `src/data/deskDecor.js` reads the JSON; tier prices in `src/data/deskDecorTiers.js`. The user's desk is `profiles.desk_setup` (`{ materialId, decorations: [{ id, x, y }] }`, x/y = center as share of the desk), always passed through `normalizeDeskSetup(saved, ownedDecor)` before use (drops decorations the user doesn't own). `DeskScene` renders it, both in the Desk tab and behind the envelope.
- Points: 1 per log ever created (trigger on `logs` insert; deleting doesn't refund), stored in `user_points (earned, spent)`; bought decorations in `user_decor`. Both are read-only to users: purchases go through the `purchase_desk_decor(decor)` RPC, and a trigger on `profiles` rejects desks with unowned paid decorations (see `20261117000000_desk_points.sql`). Materials and `free`-tier decorations are owned by everyone.
- Guest mode ("continue as guest" on the logged-out home) uses Supabase anonymous sign-in (`signInAsGuest` in `src/auth/session.js`), so it needs "Allow anonymous sign-ins" enabled in the dashboard. Guests are real `authenticated` users, so all RLS/storage policies apply unchanged; `user.is_anonymous` tells them apart.
- User data (selected lists, logs, streak/settings) lives in Supabase (`user_lists`, `logs`, `profiles`); photos in the private `log-photos` bucket at `<userId>/<logId>.jpg` + `_thumb.jpg`. Data access goes through `src/services/userData.js` and `src/hooks/useUserData.js`; localStorage is only a per-user cache (`found_cache:<userId>`).
